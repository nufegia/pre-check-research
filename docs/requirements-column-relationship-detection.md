## 1. 业务背景

### 1.1 问题由来

在学术造假场景中，数据伪造的实现方式通常不是完全随机的——造假者倾向于使用**快捷变换**来生成表面不同的数据，以减少工作量同时规避"完全重复列"这类简单检测。

两种最常见的快捷变换策略：

1. **列间线性变换**：将某一列（或某个隐含模板）通过线性公式 `Y = aX + b` 生成新列，制造"不同但相关"的变量。例如，将对照组数据乘以 1.2 作为实验组数据、将基线值加减一个常数得到干预后数据。
2. **列间高相关性填充**：将多列构造为同一基础模式的线性组合（含随机噪声），使两两之间呈现异常高的相关性，而这些变量在真实世界中本应相对独立。

当前系统（`raw_legacy.py`）中唯一的列间关系检测是**"重复列"**（`check_table_level`，第 436-454 行），它仅检测 `df[left].equals(df[right])` 的严格相等关系。这意味着：

- `col_B = col_A * 1.2` → **漏检**
- `col_B = col_A + 5` → **漏检**
- `col_B = col_A + random_noise`（r=0.98）→ **漏检**

### 1.2 已知案例

在研究数据审计实践中，已发现以下模式的造假：

- 同一指标在不同时间点的测量值，两列间存在固定常数差值（如每行恰好差 0.5），看似符合测量波动，实际为公式填充
- 多个生化指标之间 Pearson 相关系数普遍 > 0.95，而文献中同类指标的典型相关通常在 0.3-0.6 范围
- 干预后数据 = 干预前数据 × 1.1 + 随机小数，导致组间差异"恰好显著"但变量结构完全由公式决定

### 1.3 与现有检测项的关系

| 现有检测项 | 覆盖能力 | 是否覆盖本需求 | 原因 |
|------------|----------|----------------|------|
| 重复列 | 列内容完全相同（`df.equals`） | 否 | 线性变换（a≠1 或 b≠0）不会产生完全相等的列 |
| 等差/固定步长 | 单列内相邻行的差值模式 | 否 | 仅检查行间步长，不检查列间关系 |
| 分组过度相似 | 不同分组的均值/方差是否异常接近 | 否 | 检查的是分组统计量，不是列间逐行关系 |
| 多变量分组异常均衡 | 多变量在组间的分布均衡性 | 否 | 同上，关注的是组别维度而非变量间维度 |
| 近似重复行 | 相邻行的值相似度 | 否 | 行间比较，不涉及列间关系 |

**结论**：列间线性变换和高相关性是两个全新的检测盲区，需要新增独立的检测项来覆盖。

## 2. 架构需求：检测项置信度评分体系

### 2.1 背景

当前系统通过 `enrich_finding_explanation()` 对所有 finding 统一赋 `confidence` 字段，默认规则为：

```python
finding.confidence = "high" if finding.level == "high" else "medium"
```

该规则仅按信号等级（high/medium/low/info）粗暴映射，完全不反映检测项本身的方法学可信度。例如：

- 对 8 行数据进行尾数分布卡方检验，期望频次不足，检验本身不可靠，但若恰好 p < 0.05，系统可能报告 `level: medium`，`confidence: medium`
- 对 500 行大样本做同样的尾数检验，检验统计量稳定可靠，但置信度字段与上述低质量检验完全相同

**结果**：报告的置信度字段无法区分"检验条件充分的高质量信号"和"统计效力不足的低质量信号"，影响审计结论的可靠性。

### 2.2 需求概述

为每个检测项建立**数值置信度评分**机制，要求：

1. **每个检测项**在产生 finding 时，同步计算一个 0.0-1.0（或百分比 0%-100%）的置信度分值
2. 置信度分值反映**该次检测本身的方法学可信度**，而非信号强度
3. 所有检测项统一遵循相同的置信度因子框架
4. 置信度分值写入 finding 的扩展字段，供报告阶段引用

### 2.3 置信度因子框架

检测项的置信度由一组**公共因子**和**专属因子**加权计算：

```
置信度分值 = Σ(因子得分_i × 权重_i) / Σ(权重_i)
```

#### 2.3.1 公共因子（所有检测项适用）

| 因子 | 描述 | 得分规则 |
|------|------|----------|
| **样本量充足度** | 参与计算的有效样本量是否满足方法的最低要求 | 见下方通用表 |
| **数据质量** | 输入数据的缺失率、异常值比例 | 缺失率 < 5% → 1.0；5-15% → 0.7；15-30% → 0.4；> 30% → 0.2 |
| **方法假设满足度** | 检测方法的前置假设是否满足（如正态性、独立性、期望频次等） | 假设全部满足 → 1.0；部分满足 → 0.5；关键假设不满足 → 0.2 |
| **效应强度** | 信号本身的统计效应量（effect size）是否清晰 | 效应量强 → 1.0；中等 → 0.6；弱 → 0.3 |

#### 2.3.2 样本量充足度通用分级

| 有效样本量 n | 得分 | 说明 |
|-------------|------|------|
| n >= 100 | 1.0 | 大样本，统计推断稳定 |
| 60 <= n < 100 | 0.8 | 中等偏大，多数检验可靠 |
| 30 <= n < 60 | 0.6 | 中等样本，部分检验效力不足 |
| 15 <= n < 30 | 0.4 | 小样本，统计波动大 |
| n < 15 | 0.2 | 极小样本，仅适合描述性观察 |

#### 2.3.3 专属因子（按检测项类型定制）

各检测项根据其方法学特征定义专属因子。示例：

**尾数分布检验（卡方）：**

| 因子 | 权重 | 得分规则 |
|------|------|----------|
| 样本量充足度 | 30% | 见通用表，额外要求 n >= 30 才启用卡方检验 |
| 期望频次 | 30% | 每个末位数字期望频次 >= 5 → 1.0；>= 3 → 0.6；< 3 → 从该项开始置信度封顶 0.5 |
| 数据质量 | 20% | 通用数据质量因子 |
| 效应强度（偏离均匀度） | 20% | Cramér's V >= 0.3 → 1.0；>= 0.1 → 0.5；< 0.1 → 0.2 |

**Benford 首位数字检验：**

| 因子 | 权重 | 得分规则 |
|------|------|----------|
| 样本量充足度 | 25% | 见通用表 |
| 数量级跨度 | 30% | 数据跨越 >= 4 个数量级 → 1.0；2-3 个 → 0.6；1 个 → 0.2 |
| 期望频次 | 25% | 每个首位数字期望频次 >= 5 → 1.0；>= 3 → 0.6 |
| 效应强度 | 20% | MAD（mean absolute deviation）与临界值的比值 |

**等差/固定步长：**

| 因子 | 权重 | 得分规则 |
|------|------|----------|
| 样本量充足度 | 20% | 见通用表 |
| 步长占比 | 40% | 相同差值占比 >= 90% → 1.0；>= 70% → 0.7 |
| 重复次数 | 40% | 重复次数 >= 20 → 1.0；>= 10 → 0.7；>= 7 → 0.5 |

**列间线性变换（需求一）：**

| 因子 | 权重 | 得分规则 |
|------|------|----------|
| 样本量充足度 | 25% | 见通用表 |
| 拟合优度 | 50% | R² >= 0.999 → 1.0；0.995-0.999 → 0.7 |
| 斜率偏离特殊值 | 25% | a 不接近 0 或 1 → 1.0；a≈0 或 a≈1 → 0.5（可能是合法的总分/单位换算） |

**列间高相关性（需求二）：**

| 因子 | 权重 | 得分规则 |
|------|------|----------|
| 样本量充足度 | 30% | 见通用表 |
| 相关系数强度 | 40% | \|r\| >= 0.98 → 1.0；0.95-0.98 → 0.7 |
| 相关对在全表中的稀缺性 | 30% | 仅此一对高相关 → 1.0；全表 30%+ 列对高相关 → 0.6（可能是同源数据） |

### 2.4 Schema 变更

在 finding schema 中新增两个字段：

```json
{
  "confidence_score": {
    "type": "number",
    "minimum": 0.0,
    "maximum": 1.0,
    "description": "本次检测的方法学置信度分值，0.0-1.0"
  },
  "confidence_basis": {
    "type": "string",
    "description": "置信度计算的因子分解说明，便于报告阶段解释"
  }
}
```

`confidence_basis` 示例：
```
"样本量充足度=0.6(权重25%), 拟合优度=1.0(权重50%), 斜率偏离特殊值=0.5(权重25%); 加权总分=0.73"
```

### 2.5 现有 `confidence` 字符串字段的处理

保留现有的 `confidence` 字符串字段（`"high"` / `"medium"` / `"low"`）作为**信号等级对应的方法学置信度定性分类**，新增的 `confidence_score` 提供精确数值。两者转换关系：

| confidence_score | confidence (string) |
|------------------|---------------------|
| >= 0.75 | "high" |
| 0.40 - 0.75 | "medium" |
| < 0.40 | "low" |

### 2.6 报告中的置信度表达

`pcr-report merge` 在生成报告时：

1. **在每个 finding 旁展示置信度分值**：以百分比形式呈现（如"置信度: 73%"），并附上简短解释（从 `confidence_basis` 提取关键因子）
2. **低置信度信号的降权处理**：`confidence_score < 0.40` 的 finding 在报告中标注"该信号置信度较低，建议补充数据后重新检测"
3. **整体审计置信度摘要**：报告末尾汇总所有 finding 的置信度分布，帮助读者判断本次审计的整体可靠性
4. **交付报告中的表达**：`pcr-delivery-report` 引用置信度分值来辅助优先级排序，高信号+低置信度的 finding 不应排在最高复核优先级

### 2.7 实现策略

| 阶段 | 内容 |
|------|------|
| 第一阶段 | 在 `add_finding()` 中增加 `confidence_score` 和 `confidence_basis` 参数；为现有 12 项基础表格规则检测逐一补充置信度计算逻辑 |
| 第二阶段 | 为 crosscheck（行级数学交叉校验）和 p_value_distribution 补充置信度因子 |
| 第三阶段 | 为 R 工具（statcheck、scrutiny、rsprite2）设计基于样本量和检验假设的置信度因子 |
| 第四阶段 | 更新 `pcr-report merge` 和 `pcr-delivery-report` 以解析和展示置信度分值 |

### 2.8 验收标准

- [ ] 所有检测项（raw_data_rules 下 12 项 + crosscheck 下 10 项 + p_value_distribution 下 2 项）均输出 `confidence_score`（数值）和 `confidence_basis`（字符串）
- [ ] `confidence_score` 始终在 [0.0, 1.0] 范围内
- [ ] 小样本（n < 15）检测的 `confidence_score` 不超过 0.40
- [ ] `confidence_basis` 包含各因子得分和权重的可读说明
- [ ] 报告生成器正确展示置信度百分比和降权标注
- [ ] 现有测试更新后通过

## 3. 清理需求：合并数字分布检测到基础表格规则

### 3.1 现状

当前系统存在两个独立的基础表格检测工具：

| 工具 ID | 函数 | 包含的检查项 |
|---------|------|-------------|
| `raw_data_rules` | `analyze_raw_data_rules()` | 空表、缺失模式、重复行、重复列、高频数值、小数位模式、等差/固定步长、连续重复值、离群值、分组过度相似 |
| `digit_distribution` | `analyze_digit_distribution_rules()` | 尾数分布、Benford 首位数字分布 |

在路由配置（`router.py:13`）中，`raw_observation_table` 类型的输入同时路由这两个工具：

```python
(("raw_observation_table", "figure_source_data"), ("raw_data_rules", "digit_distribution")),
```

### 3.2 问题

`digit_distribution` 仅包含 2 项检查（尾数分布、Benford），概念上它们与 `raw_data_rules` 中的其他列级数值检查（如小数位模式、高频数值）属于同一层次，都是"对数值列的单变量分布特征进行检查"。单独拆分为独立工具造成：

1. **概念冗余**：数字分布检测本质上就是基础表格规则的一部分，不应独立成工具
2. **路由冗余**：每张表需要两次工具调用来完成实际同一层面的检查
3. **报告冗余**：两份独立的 finding JSON 却描述同一张表的同类问题，增加合并阶段（`pcr-report merge`）的复杂度
4. **维护负担**：两套独立的 `tag_findings` 调用、两套工具元数据注册

另外，`raw_legacy.py` 中的 `analyze_table()`（第 1325 行）作为旧版兼容函数，同步调用了这两个函数，合并后也需要一并更新。

### 3.3 清理方案

将 `analyze_digit_distribution_rules()` 中的两项检查合并到 `analyze_raw_data_rules()` 内部：

**变更前：**
```python
def analyze_raw_data_rules(...):
    # 现有 10 项检查
    check_table_level(name, df, findings)
    for col, values in num_cols.items():
        check_dominant_values(...)
        check_decimal_precision(...)
        check_arithmetic_sequences(...)
        check_outliers(...)
    check_group_similarity(...)
    tag_findings(findings, "raw_data_rules", ...)

def analyze_digit_distribution_rules(...):
    # 2 项检查
    for col, values in num_cols.items():
        check_terminal_digits(...)
        check_benford(...)
    tag_findings(findings, "digit_distribution", ...)
```

**变更后：**
```python
def analyze_raw_data_rules(...):
    # 合并后共 12 项检查
    check_table_level(name, df, findings)
    for col, values in num_cols.items():
        check_dominant_values(...)
        check_decimal_precision(...)
        check_arithmetic_sequences(...)
        check_outliers(...)
        check_terminal_digits(...)      # ← 从 digit_distribution 合并
        check_benford(...)              # ← 从 digit_distribution 合并
    check_group_similarity(...)

```

## 4. 增强需求：完全重复检测扩展为高度重复检测

### 4.1 背景

当前基础表格规则中的重复检测仅覆盖**完全相等**的情形：

| 检测项 | 当前逻辑 | 函数 | 阈值 |
|--------|----------|------|------|
| 重复行 | `df.duplicated()` 全列精确匹配 | `check_table_level` | 100% 列值相等 |
| 重复列 | `df[left].equals(df[right])` | `check_table_level` | 100% 行值相等 |

另在 `raw.py` 中存在独立的"近似重复行"检测（`_append_near_duplicate_rows`），但仅检查**相邻行**，阈值为 85%，且与 `check_table_level` 分离，未形成统一的重复检测层次。

**漏检场景**：
- 造假者复制某行后改动 1-2 个字段（如只改分组标签），产生 90% 相似但非完全相等的行 → 完全重复行**漏检**
- 造假者复制某列后修改少量值（如改动 5% 的异常值），产生 95% 相似但非完全相等的列 → 完全重复列**漏检**
- 非相邻行（如第 2 行与第 45 行）高度相似 → 近似重复行（仅检相邻）**漏检**

### 4.2 需求概述

将"完全重复行"和"完全重复列"两项检测**扩展为三层递进检测**：

```
完全重复 (100%)  ──→  高度重复 (≥90%)  ──→  近似重复 (≥85%)
   现有能力              本次新增            本次新增（吸收合并）
```

具体扩展内容：

1. **完全重复行 → 扩展为"高度重复行"检测**：对所有行两两比较（不限于相邻），非空列值相同比例 >= 90% 时报告
2. **完全重复列 → 扩展为"高度重复列"检测**：对所有数值列两两比较，非空行值相同比例 >= 90% 时报告
3. **移除并吸收现有"近似重复行"**：`raw.py` 中的 `_append_near_duplicate_rows`（仅检相邻行，阈值 85%）作为独立检测项**移除**，其检测能力吸收到统一的行重复框架中——新框架同时覆盖相邻和非相邻行，统一使用 85%/90%/100% 三层阈值

### 4.3 检测逻辑设计

#### 4.3.1 高度重复行

**输入**：单表（DataFrame），所有列参与比较

**策略**：
1. **行签名计算**：为每行生成非空值签名（跳过 NaN）
2. **候选配对筛选**：对行数 > 50 的表，先按行签名哈希分桶，仅对同桶内的行进行两两比较（降低 O(n²) 开销）
3. **相似度计算**：对候选行对 `(row_A, row_B)`，计算 `相同非空列数 / 可比列数`（可比列 = 两行均非空的列）
4. **阈值判断**：
   - 相似度 = 100% → 完全重复行（沿用现有 high 等级）
   - 相似度 >= 90% → 高度重复行（新增 high/medium）
   - 相似度 >= 85% → 近似重复行（整合 `_append_near_duplicate_rows`）
5. **去重报告**：同一行参与多个重复组时，选择相似度最高的一组报告

**信号分级**：

| 条件 | 等级 | 说明 |
|------|------|------|
| 相似度 100%（完全重复） | **high** | 精确复制，现有逻辑保持不变 |
| 相似度 >= 95% | **high** | 仅个别字段不同，强烈提示选择性篡改 |
| 90% <= 相似度 < 95% | **medium** | 高度相似，需排除合理共享字段 |

**输出样例**：
```json
{
  "level": "high",
  "check": "高度重复行",
  "target": "整表",
```

#### 4.3.2 高度重复列

**输入**：单表（DataFrame），所有列参与比较（排除索引列）

**策略**：
1. 对所有列两两配对，对每对 `(col_A, col_B)` 计算 `相同非空行数 / 可比行数`
2. 排除完全相等的列对（已被"重复列"覆盖，避免重复报告）
3. 阈值判断：
   - 相似度 = 100% → 完全重复列（沿用现有逻辑）
   - 相似度 >= 90% → 高度重复列（本次新增）
4. 区分数值列和文本列：数值列额外计算归一化差异（`|a-b|/max(|a|,|b|)`），若所有行归一化差异 < 1% 且相似度 >= 90%，则提升信号等级

**信号分级**：

| 条件 | 等级 | 说明 |
|------|------|------|
| 相似度 100%（完全重复） | **medium** | 精确复制，现有逻辑保持不变 |
| 相似度 >= 95% | **high** | 仅极少数行不同，强烈提示列复制后微调 |
| 90% <= 相似度 < 95% | **medium** | 高度相似，需排除合理的列间关系 |

#### 4.3.3 与现有"列间线性变换"和"列间高相关性"的关系

高度重复列与需求一（线性变换）、需求二（高相关性）构成递进关系：

```
完全重复列 (100%) → 高度重复列 (≥90%) → 线性变换 (R²→1.0) → 高相关性 (|r|→1.0)
```

- **高度重复列**检测的是**逐行值相等**的比例（离散匹配），适合混合类型列
- **线性变换**检测的是**确定性函数关系**（连续拟合），仅适用于数值列
- **高相关性**检测的是**统计依赖**，适用于存在噪声的数值列

三类检测互补，不应互相替代。

### 4.4 性能优化

行间全对比较的复杂度为 O(n²×m)（n=行数，m=列数）。优化策略：

1. **行签名哈希分桶**：对每行非空值计算 MinHash 或局部敏感哈希（LSH），仅对同桶内行进行比较
2. **行数阈值**：行数 <= 50 → 全对比较；行数 > 50 → 启用哈希分桶
3. **列优先剪枝**：先执行列间比较（列数通常 << 行数），若某列已被标记为与另一列高度重复，行间比较时可降低该列的权重
4. **可配置上限**：通过配置项限制最大行对比较数，防止极端宽表/长表导致超时

## 6. 需求一：列间线性变换关系检测

### 6.1 功能概述

检测同一表格中两列数值列之间是否存在线性变换关系，即 `col_B ≈ a × col_A + b`（a 和 b 为常数）。

### 6.2 检测目标

造假者将某列经过简单线性变换后作为另一列提交，典型模式：

- 同一指标的"干预前/干预后"数据，差值恰好恒定
- 不同实验组的同类指标，存在固定比例关系
- 量表子维度之间呈现完美的线性映射

### 6.3 检测逻辑设计

#### 6.3.1 输入

- 单表（DataFrame），仅分析其中数值列
- 排除已被标记为结构性索引列（如序号、编号列，通过 `is_structural_index_column` 判断）

#### 6.3.2 检测策略

对表中所有数值列进行两两配对（列配对），对每对 `(col_A, col_B)` 执行：

1. **数据清洗**：去除 `col_A` 或 `col_B` 中任一为 NaN 的行
2. **样本量门槛**：有效配对行数 >= 10
3. **排除完全相等**：若 `col_A.equals(col_B)`，跳过（已被"重复列"检测覆盖）
4. **线性回归拟合**：以 `col_A` 为自变量，`col_B` 为因变量，拟合 `col_B = a × col_A + b`
5. **拟合优度判断**：
   - 计算决定系数 R²
   - 若 R² >= 0.995（可配置），认为存在线性变换关系
   - 额外计算平均绝对百分比误差（MAPE）作为辅助判据
6. **固定差值特例**：若 `a ≈ 1.0`（在容差范围内），则识别为"固定差值"模式，等效于 `col_B ≈ col_A + b`

#### 6.3.3 信号分级

| 条件 | 信号等级 | 说明 |
|------|----------|------|
| R² >= 0.999 | **high** | 近乎完美线性关系，强烈提示公式变换 |
| 0.995 <= R² < 0.999 | **medium** | 高度线性关系，需排除实验设计相关性 |
| R² >= 0.999 且 a≈1（固定差值） | **high** | 固定差值模式，典型的"加减常数造假" |

#### 6.3.4 输出格式（符合 finding.schema.json）

```json
{
  "level": "high",
  "check": "列间线性变换",
  "target": "col_A → col_B",
  "summary": "列 B 与列 A 之间存在近似完美的线性变换关系。",
  "evidence": "线性拟合 R²=0.9998，回归式: col_B = 1.2003 × col_A + 0.5012",
  "detail": "对表内 12 个数值列进行两两配对线性拟合，共检测 66 对。col_A→col_B 的 R²=0.9998 超出阈值 0.995。若这两个变量在专业上应保持独立，该关系强烈提示公式填充。",
  "suggestion": "逐行比对两列原始记录，确认是否存在公式变换；检查两个变量在研究设计中是否本应存在函数关系。",
  "meaning": "列间线性变换通常表明一列是由另一列通过固定公式生成，而非独立测量获得。",
  "normal_explanations": "总分与子分关系、温度单位换算、浓度稀释计算等物理/数学推导关系。",
  "review_steps": "1. 确认两列在研究中的语义关系（是否本应是函数关系）。2. 若不应线性相关，要求提交原始测量记录比对。3. 检查实验记录本中两指标是否为同一时间点独立测量。",
  "confidence": "高（R² 极高时误报风险低）",
  "false_positive_risk": "低。主要误报来源：总分/子分关系、物理单位换算、浓度的系列稀释等合法函数关系。"
}
```

#### 6.3.5 排除场景（减少误报）

- 已被 `is_structural_index_column` 标记的列（序号、编号等）
- 列对中 `col_A.equals(col_B)` 的完全重复列（已被"重复列"覆盖）
- 可在配置中指定已知的函数关系列对白名单（如"总分"与"子分"）

## 7. 需求二：列间过高相关性检测

### 7.1 功能概述

检测同一表格中两列数值列之间是否存在异常高的统计相关性（Pearson 或 Spearman），这种相关性超出了该研究领域中同类变量的典型相关水平。

### 7.2 检测目标

与需求一互补：需求一检测**确定性线性变换**，需求二检测**非确定性但异常高的相关性**。典型造假模式：

- 造假者基于同一个随机模板生成了多列数据，虽然加入了噪声使得不满足严格线性变换，但列间相关性仍然远高于真实数据的应有水平
- 量表多个条目之间的相关性异常一致且偏高（例如所有条目间 r 都在 0.85-0.92 之间），而真实量表通常存在低相关甚至负相关的条目对
- 同一表格中所有数值列构成一个高度冗余的相关矩阵，缺乏真实数据的独立变异特征

### 7.3 检测逻辑设计

#### 7.3.1 输入

- 单表（DataFrame），仅分析其中数值列
- 排除索引列

#### 7.3.2 检测策略

对表中所有数值列进行两两配对，对每对 `(col_A, col_B)` 执行：

1. **数据清洗**：去除任一列为 NaN 的行
2. **样本量门槛**：有效配对行数 >= 10
3. **相关性计算**：
   - 主检测：Pearson 相关系数 r（适用于近似线性关系）
   - 辅助检测：Spearman 秩相关系数 ρ（适用于单调非线性关系）
4. **异常判断**：
   - 单对相关性过高：\|r\| >= 0.95（可配置）
   - 全表相关性结构异常：数值列两两相关系数中位数 >= 0.80，或所有显著相关的列对占比过高
5. **聚合信号**：
   - **单对过高**：逐个报告每对异常高相关的列
   - **整体异常**：当高相关列对占比超过全表列对的 50% 时，额外报告一个 table-level 的"相关矩阵异常"信号

#### 7.3.3 信号分级

| 条件 | 信号等级 | 说明 |
|------|----------|------|
| 单对 \|r\| >= 0.98 | **high** | 近乎完美相关，虽非严格线性变换但极为可疑 |
| 单对 0.95 <= \|r\| < 0.98 | **medium** | 异常高相关，需核查变量独立性 |
| 全表数值列高相关占比 >= 50% | **high** | 整体相关矩阵结构异常，提示系统性构造 |
| 全表数值列高相关占比 30%-50% | **medium** | 相关矩阵偏高，需结合领域知识判断 |

#### 7.3.4 输出格式

```json

  "level": "high",
  "check": "列间过高相关性",
```

## 8. 需求三：非连续变量离群值检测

### 8.1 背景

当前基础表格规则中的离群值检测（`check_outliers`，`raw_legacy.py:625`）仅覆盖**连续数值列**：使用稳健 Z 分数（MAD），检测与中位数偏离超过 3.5 倍 MAD 的极端值。该检测对以下变量类型**完全无效**：

- **分类变量**（无序）：如性别、城市、治疗方法等，无法计算数值距离
- **有序变量**（含序号的类别）：如 Likert 量表评分（1-5）、教育程度（1-4）、疾病分期（I-IV）
- **低基数离散变量**：如事件发生次数（0, 1, 2, 3+），取值只有少数几个可能值

这些变量类型在研究数据中极为常见，且同样存在造假信号。典型的异常模式包括：

- 某分类变量的罕见类别仅出现 1-2 次（如 50 例患者中仅 1 例"其他"），可能是为凑满预设分布而强行添加
- Likert 量表 200 个评分中仅最小值（1）和最大值（5）有值，中间类别完全缺失，提示数据可能来自两极化构造而非真实分布
- 有序变量的取值集中在两端（U 形分布），与预期的正态或偏态分布严重不符

### 8.2 需求概述

新增两项非连续变量的离群检测：

1. **低频类别检测**：识别分类变量中频次极低（孤立）的类别
2. **有序变量极端集中检测**：识别有序/离散变量中取值集中于两端的异常分布模式

### 8.3 检测逻辑设计

#### 8.3.1 低频类别检测

**输入**：表中所有非数值列（`object`、`category` 类型）及低基数列（唯一值 <= 20 的整数列）

**策略**：
1. 对每列计算各类别的频次分布
2. 识别频次占比 < 5% 且绝对频次 <= 2 的类别（"孤立类别"）
3. 若存在孤立类别，且孤立类别之外的类别数量 >= 3（排除二分类变量），则报告
4. 额外判断：若孤立类别占全表行数 < 1% 且仅出现 1 次，提升为 high 信号（高度可疑的"凑数"模式）

**信号分级**：

| 条件 | 等级 | 说明 |
|------|------|------|
| 孤立类别仅出现 1 次且占比 < 1% | **high** | 极可能是为满足分布要求而人为添加 |
| 孤立类别占比 < 5% 且频次 <= 2 | **medium** | 罕见类别，需确认是否为合理的数据编码 |
| 存在多个孤立类别（>= 2 个） | **high** | 多个罕见类别同时出现，提示数据构造 |

**排除场景**：
- 二分类变量（恰好 2 个类别）不检测——例如性别（男/女）本身就低基数
- 已被 `is_structural_index_column` 排除的列
- 唯一值 > 20 的列（可能是高基数文本列，不适合此检测）

**输出样例**：
```json
{
  "level": "high",
  "check": "低频类别",
  "target": "treatment_group",
  "summary": "分类变量中存在极低频率的孤立类别，可能为凑分布而人为添加。",
  "evidence": "类别'其他': 1/200 (0.5%)；类别分布: A组=98, B组=101, 其他=1",
  "detail": "该列共 3 个类别，其中'其他'仅出现 1 次（占比 0.5%），其余类别分布相对均匀。这种在均衡分组中突然出现单一孤立类别的模式，提示可能是为满足某种预设分类框架而强行补充的异常值。",
  "suggestion": "核实该孤立类别的样本来源，确认是否为数据录入错误、编码映射错误或人为添加。",
  "meaning": "孤立类别在原本类别数较少的变量中异常突出，可能是数据构造的特征。",
  "normal_explanations": "有效的'其他'类（开放式问卷的补充回答）、数据清洗后的残余值、真实存在的罕见情况（如罕见病亚型）。",
  "review_steps": "1. 回溯原始问卷/记录，确认该类别对应的样本是否真实存在。2. 检查该样本的其他变量值是否也呈现异常模式。3. 确认数据编码表中是否定义了该类别。",
  "confidence": "中",
  "false_positive_risk": "中。真实的罕见亚型、开放式问卷的自由文本编码等均可能产生孤立类别。"
}
```

#### 8.3.2 有序变量极端集中检测

**输入**：表中整数型列（唯一值 3-15 个），特别是列名包含"评分""等级""分级""scale""score""grade""level""stage"等关键词的列

**策略**：
1. 对每列计算取值分布：按值排序后，计算两端的累积占比
2. **双峰/两端集中判断**：
   - 最小值 + 最大值两类的合计占比 >= 80% → 高度两端集中
   - 最小值 + 最大值两类的合计占比 >= 60% 且中间类别占比 < 20% → 中度两端集中
3. **中间类别缺失判断**：若某个中间取值出现频次为 0（如 Likert-5 中"3"出现 0 次），额外标记为分布不连续
4. **熵值判断**（辅助）：计算 Shannon 熵，若熵值低于理论均匀分布熵值的 50%，说明分布过于集中

**信号分级**：

| 条件 | 等级 | 说明 |
|------|------|------|
| 两端合计 >= 80% 且存在中间类别缺失 | **high** | 极端的 U 形分布，强烈提示数据两极化构造 |
| 两端合计 >= 80%，无中间缺失 | **medium** | 高度两端集中 |
| 两端合计 60%-80% | **low** | 偏两端集中，可能为真实分布特征 |
| 中间类别缺失（断层） | **medium** | 分布不连续，可能为人为跳过某些取值 |

**排除场景**：
- 二元变量（唯一值 <= 2）
- 唯一值 > 15 的变量（接近连续变量，应使用 `check_outliers`）
- 已知的合法双峰分布（如医学指标的性别分层）

**输出样例**：
```json
{
  "level": "high",
  "check": "有序变量极端集中",
  "target": "anxiety_score",
  "summary": "有序变量的取值高度集中于两端，中间类别完全缺失，呈现典型的 U 形分布。",
  "evidence": "评分1: 42 (21%), 评分2: 0 (0%), 评分3: 0 (0%), 评分4: 5 (2.5%), 评分5: 153 (76.5%)；两端合计=97.5%，中间缺失",
  "detail": "anxiety_score 为 1-5 的 Likert 评分，200 个观测中评分 2 和 3 的频次均为 0，而评分 1 和 5 合计占比 97.5%。真实的量表数据中极端两极化分布极为罕见，通常应呈现一定程度的中间响应。",
  "suggestion": "核对原始量表，确认是否存在评分者偏差、量表翻译问题或数据构造。对该变量的采集流程进行专项审查。",
  "meaning": "有序变量仅在两端取值而中间空白，通常表明数据非真实测量产生，可能是人为分配到两极。",
  "normal_explanations": "极端的群体极化现象、经过预筛选的极端群体样本、特定的人格量表（如某些成瘾量表确实天然两极分化）。",
  "review_steps": "1. 查阅该量表在同类人群中的典型分布是否同样呈现两极模式。2. 随机抽取评分 1 和评分 5 的样本，核查原始问卷。3. 检查是否存在量表条目翻译或文化适应问题导致中间选项失效。",
  "confidence": "中",
  "false_positive_risk": "中高。特定量表天然存在两极分化（如临床筛查量表），需领域知识判断。"
}
```

## 9. 两项需求的互补关系

```
                    ┌─────────────────────────────────┐
                    │     列间关系异常检测体系          │
                    └─────────────────────────────────┘
                                    │
            ┌───────────────────────┼───────────────────────┐
            ▼                       ▼                       ▼
    ┌──────────────┐       ┌──────────────┐       ┌──────────────┐
    │   重复列      │       │  线性变换检测  │       │  高相关性检测  │
    │  (已有)       │       │  (需求一/新增) │       │  (需求二/新增) │
    └──────────────┘       └──────────────┘       └──────────────┘
    col_A == col_B         col_B = a·col_A+b     col_A ~ col_B
    严格相等                R² → 1.0              |r| → 1.0
                           确定性关系             强统计依赖

覆盖面递增 ──────────────────────────────────────────────────────►
误报率递升 ──────────────────────────────────────────────────────►
证据强度递减 ────────────────────────────────────────────────────►
```

三项检测构成递进覆盖：
- **重复列**：最严格、证据最强、误报最低，但覆盖面最窄
- **线性变换**：覆盖确定性变换，包括重复列无法覆盖的 `col_B = col_A + 5` 和 `col_B = col_A × 1.2` 等模式
- **高相关性**：覆盖非确定性构造，包括添加了噪声的模板生成模式，覆盖面最广但需领域知识辅助判断

### 10.2 与路由系统的关系

建议作为 `raw_data_rules`（基础表格规则）的新增子检查项。原因：
- 输入类型相同（`raw_observation_table`）
- 无需额外的 R 依赖
- 与现有"重复列"检测属于同一逻辑层次

### 10.3 性能考量

- 列间两两配对复杂度为 O(n²)，其中 n 为数值列数
- 典型研究表格 n ≤ 30，计算量可控
- 对于列数 > 100 的宽表，建议先按列名模式（前缀、后缀）分组，仅对同组列进行配对检测
- 可选：支持 `--max-column-pairs N` 参数限制最大检测对数
